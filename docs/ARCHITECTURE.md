# 底层算法与重构说明（v0.2）

## 一句话

这是固定时段推进的多智能体模拟（Agent-based simulation），NPC 用效用评分（Utility AI）做选择，社交由规则和可复现的随机检定结算。没有训练模型、强化学习或必须在线的大模型代理。

## 一个时段如何发生

```mermaid
flowchart LR
  A[全部角色需求衰减] --> B[基于自身状态和局部信息评分]
  B --> C[各自选最高分行动]
  C --> D[统一移动与结算需求]
  D --> E[记录亲眼目击]
  E --> F[邀约与独立回应]
  F --> G[同地点自主互动]
  G --> H[关系与重要记忆更新]
  H --> I[事件记录与日终手记]
```

先计算所有人的行动，再统一移动。这样先执行的角色不会向后执行者泄露自己即将去哪里。地图的动画仅补间两个已确定状态，不影响模拟。

## 决策

候选行动评分概括为：

`总分 = 需求和目标 + 兴趣/习惯 + 关系动机 - 回避 - 生理负担 + 种子波动`

普通行动有休息、吃饭、上课、自习和参加社团。角色对自己的兴趣地点有偏好，对固定时段还有习惯加成。基于已知位置可以增加找熟人或尝试澄清的候选行动；好感、信任、心动和社交需求影响分数。饥饿与疲劳可以压过邀约意愿。每个候选的评分组成会记录在事件中。

这是一种短期、逐时段的贪心决策。角色尚不搜索多步计划，也不推理最优一周策略。对十人规模足够便宜、可调试，并能逐步叠加小计划。

## 局部信息与自主社交

每人保存亲眼看到的最后位置，以及最多四个时段的目击习惯。不读取别人的实时位置来选择行动：最近目击有效三时段，同一时段的习惯预测有效八时段。推测可能过时，找不到会产生擦肩事件并标记这条线索失效。

同地点互动在所有角色行动后发生。宿舍额外要求同室。主动邀约优先结算，受邀者独立按自身需求、性格、好感、信任和种子波动决定是否接受，不会被发起者强制移动。其余角色对同地点候选者做关系加权抽样，再检查误解、澄清、竞争、单向心动和普通交流规则。

误解有具体场景和双方解释，但仍是简化的规则解释；尚未实现任意命题的信念系统或第三方传话。学业目标、兴趣与需求已参与决策，目标本身仍固定。

## 记忆与关系

关系是有方向的好感、信任和心动。误解对双方影响可以不同，心动只改变发起方。澄清等规则更新关系，再影响将来的选择。

每人最多保留八条亲历事件，按 `事件重要性 - 年龄 × 0.16` 排序；普通移动会比重要关系经历更快被挤掉。目击信息是单独有时限的局部位置缓存，每人最多知道其他九人、每人四个时段，不能任意读取全局日志。

玩家可查看全局记录；规则决策只能访问自己的状态、亲历记忆、可见环境和目击缓存。

## 确定性与存档

种子经过整数混合初始化 Mulberry32 随机序列。所有决策波动、配对和检定都通过这一条受控序列。播放速度、日期、动画与 DOM 不进入内核。

存档包含 schemaVersion、engineVersion、seed、tick、inputs 和状态校验值。导入会校验范围和干预顺序，再从种子重跑，比较完整状态校验；不直接信任导入文件中的 NPC 对象。校验是差错检测，不是密码学签名。

v0.2 规则变化会改变同种子的结果，暂不兼容 v0.1 存档，也不承诺跨引擎版本重放。浏览器本机保存还包括所选角色、关注列表、跟随状态和筛选方式；恢复后默认暂停。

## 因果追踪

事件含递增 ID、时段、类型、人物、重要度、数据与前置事件 ID，父边只能指向更早的事件。行动指向自身历史、用到的目击证据和相关环境变化；互动连接双方前置经历、邀约与回应；日终手记选出最多三个不同人物组合的代表事件。

行动记录还包含当时实际看见的人，便于验证位置线索的来源。此处提供规则执行的因果链，不声称已完成反事实因果推断。

## 为什么局部重构

旧版把需求、评分、移动、社交、记忆和摘要集中在 World.step，新增规则容易耦合。v0.2 保留内核边界并拆为：

| 模块                | 职责                                 |
| ------------------- | ------------------------------------ |
| src/sim/config.js   | 版本、周期、十人档案                 |
| src/sim/random.js   | 种子与可复现随机序列                 |
| src/sim/decision.js | 候选行动和可解释评分                 |
| src/sim/social.js   | 邀约、回应、配对、关系规则           |
| src/engine.js       | 推进阶段、世界状态、事件、记忆、存档 |
| src/ui/map.js       | 持久化小人节点、路径移动与昼夜       |
| src/ui/views.js     | 角色档案、关系图、时间线与每日手记   |
| src/app.js          | 播放、干预、关注、导入导出、本机保存 |

十人、五地规模下，配对与局部观察的 O(N²) 开销很小；无需现在引入复杂空间索引、通用 ECS、服务端集群或每人一个大模型。以后若扩大到大量 NPC、长周期或多人，再评估空间索引、事件调度、后台计算与快照。
