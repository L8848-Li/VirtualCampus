# v0.3 之后，从哪里继续优化

这是 v0.3 阶段的脑暴记录，其中故事卡、两类有来源的认知及 NPC 自主小聚已在 v0.4 落地，当前范围见 [v0.4 设计说明](ITERATION-v04.md)。下文其余条目仍是建议。

## 当前观察

本轮解决了组件化、类型边界、计划持续性和具体共同事务。100 个固定种子中，饭约约 84% 兑现、报告约 96% 完成，已经能产生中断和错过。当前更值得研究的是失败如何被理解、谁知道什么，以及玩家能否顺着一件事一直看下去。

## 优化角度

| 角度         | 可做的下一步                                               | 价值                                     |
| ------------ | ---------------------------------------------------------- | ---------------------------------------- |
| 信息差       | 记录谁看见了什么、消息来源与置信度，允许当事人向第三者求证 | 误解有具体事实来源，澄清更有后劲         |
| 合作中的公平 | 用已有贡献记录表达谁做了工作、谁的付出被看见               | 竞争与不满从实际事务自然形成             |
| 故事阅读     | 把同一个 planId / taskId 的事件聚成一张可展开故事卡        | 玩家不用在大量日志中拼接来龙去脉         |
| 性格成长     | 让反复的成功、拒绝与失约缓慢改变习惯和目标                 | 角色一周后留下可识别的成长痕迹           |
| 稀缺资源     | 加入图书馆座位、参考书或社团设备容量                       | 合作、让步和争抢有真实机会成本           |
| 干预取舍     | 活动主题、时段、预算与有限额度                             | 玩家需要考虑哪些人会受益、谁会错过       |
| 世界对照     | 从同一历史分叉，只改变一项干预，并拆分随机流               | 更容易理解环境影响，减少无关随机连锁干扰 |
| 校园表现     | 角色兴趣道具、真正的座位、交接物品和等待动作               | 仅观察地图也能认出人物和事情             |
| 可分享与开源 | 有版本的场景包、角色配置与重放文件                         | 社区可以分享新校园，而不依赖服务器       |
| 节奏与目标   | 安静时段、每周一个公开里程碑、七日关系回顾                 | 玩家有期待，也有消化故事的空间           |

## 最推荐的三个小版本

### 1. 一件事看得懂

把饭约从提出到错过、解释的整个链条聚合成故事卡。卡片同时展示观察者知道的事实、每个角色知道的信息和当前悬而未决的问题。先改善已有内容的可读性，不急于增加 NPC 数量。

### 2. 付出会被看见

在报告贡献记录之上增加“谁注意到了谁的付出”。付出多不必自动不满，性格、认可和分工承诺决定反应；被误认为没做事的人有澄清机会。这样信任、竞争和委屈都能落到具体事实。

### 3. 可以试另一个如果

保存某时段的分支，在平行世界里取消一次活动或调整分组。先明确相同的历史与变化项，再考虑按角色 / 用途拆分随机序列，防止无关随机消耗淹没真正的干预差异。

## 如何判断更好

除现有指标，再观察玩家是否能记住三个人、讲出一段有前因后果的关系故事，以及愿不愿意在七天结束后再开一个世界。行为类别变多可能只是新增了动作；完成率更高也不自动代表更有趣。新的玩法需要配合实际游玩记录和小范围反馈。
