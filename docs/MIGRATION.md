# v0.16 → v0.17 迁移与验证说明

更新日期：2026-10-30。v0.17 保留 12 位人物、168 时段和现有完整校园日常，调整测试、事件与评分表示、历史查询和保存校验。运行时依赖与静态部署方式保持一致。

## 玩家存档

| 项目 | v0.16 | v0.17 |
|---|---|---|
| 引擎版本 | 0.16.0 | 0.17.0 |
| 存档 schema | 3 | 4 |
| 本机存档键 | `virtualcampus.save.v16.0` | `virtualcampus.save.v17.0` |
| 开发测量键 | `virtualcampus.performance-test.v16.0` | `virtualcampus.performance-test.v17.0` |
| 校验 | 整个世界 JSON | 当前状态与增量历史摘要 |

首次使用 v0.17 需新建世界。原有 v0.16 本机记录不会被覆盖或删除；设置面板发现旧记录时提供“下载旧版备份”，下载内容保持原样，需用对应旧版本恢复。

导入仍验证版本、种子、时段、输入数量与顺序、生活实验选项，再从种子重建并核对校验。v0.17 不接受 v0.16 的旧校验，也不直接导入外部人物状态。自动保存仍在每次推进与干预后立即执行，写入失败保留导出提示。

## 内核与界面接口

- `World.step()`、`intervene()`、`replay()`、`toSave()`、`fromSave()` 保留入口。
- 使用 `getState()` 取得明确的模拟状态；其中包含随机数状态和干预环境，不含界面、查询索引或评分缓存。
- 完整评分由事件 ID 关联，使用 `getActionScores(eventId)` 读取。旧的 `event.data.scores` 不再是评分访问入口。
- `events` 是只读容器视图；`getCommittedEvents()` 返回独立列表，列表中的已提交事件及嵌套内容均冻结。测试或诊断需要完整世界时，应结合状态、事件与评分读取接口，不能依赖对 `World` 实例直接做 JSON 序列化。
- 时段内部只能补充待提交事件；发布后的事实不再原地修改。恢复、重放和新建世界使用新的历史与查询缓存。

当前阶段顺序由 `core/tick.ts` 明确组织；共享配置位于 `courseCatalog.ts`，数值工具位于 `math.ts`。具体约束见[架构说明](ARCHITECTURE.md)。

## 验证入口变化

| 命令 | 覆盖范围 |
|---|---|
| `npm test` | 定向规则、共享场景、代表种子与关键点恢复 |
| `npm run test:full` | 全部测试；同步比对扩展为 100 种子 × 生活实验关闭/开启 |
| `npm run test:replay:full` | 单独执行完整同步比对与关键点恢复 |
| `npm run evaluate` | 首周 100 种子评估，核对原版指标 |
| `npm run evaluate:semester` | 30 组共享学业/科研/社团场景及 30 对生活实验 |
| `npm run verify` | 类型检查、完整测试、两类评估、构建 |

旧的逐时段从头重放改为两个独立世界同步推进，每步比较完整当前状态、新增事件与评分，并在终点比较完整历史。恢复入口由种子 0、1、99 在生活实验两种模式的 17 个检查点分别导入，并续跑至结束。测试结构发生变化，不再声称穷举所有从头重放前缀。

`tests/fixtures/v016-behavior.json` 保存原版 `b5fa1c1` 的六组逐时段行为摘要与首周评估。验证不自动重写基线；后续若有意改变玩法，应明确记录差异和版本影响。

## 交付结果与后续

本机 Node 24.16.0 验证：常规 167 项通过，29.8 秒；完整 361 项通过，75.83 秒；整套验证 91.76 秒。保存校验 P95 约 0.612 毫秒，测量进程峰值内存约下降 41%，代表历史编码体积约下降 68%。方法与原始记录见[性能报告](PERFORMANCE.md)。

常规测试的 20 秒目标尚未达到。后续优先处理仍重复的受控场景与验证计算，保持种子、恢复检查、全部评分和事实追溯。当前不扩大人物规模或引入新的常驻后台系统。Node 22 的兼容检查在 GitHub CI 执行，其结果应与本机 Node 24 验证分开记录。
