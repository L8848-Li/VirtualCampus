# VirtualCampus · 邮邮大学

> 十二个独立的小世界，在同一座校园慢慢交织。

校园背景的半上帝模式微型生命模拟器。观察 12 位 NPC 自主生活与关系故事，通过改变环境影响相遇。**v0.17.0 使用 Vue 3 + TypeScript + Vite，模拟核心独立、规则可解释、无需大模型 API 密钥。**

NPC 会记住一起吃饭的约定、为小组报告安排专注时间，也可能中断、等待或错过。一次简短回应和失约会留下有来源的猜测，后来的解释也可能不被相信。有人会在相处中萌生办兴趣小聚的愿望，自己邀请伙伴、准备材料，也可能最终没能办成。玩家改变机会，角色自己决定。

首页为“校园观察”，地图是依据用户提供的沙河校区示意布局重新绘制的原创 SVG，保留主要建筑与道路的相对位置；这不是测绘级一比一复刻。地图可放大、拖动和定位；地点圈点汇总人物，建筑活动按人物实际行动分组，可逐个观察；画面不是精确室内位置。22 处圈点对应当前可到达的模拟地点；参考图中的科研楼、北区餐厅、学院楼、体育馆、南侧运动场和两处宿舍区按虚构建成状态投入使用。宿舍 IV 区区分公共空间与私人房间并有模拟住户；研究生公寓区分公共空间与私人房间，两位研究生在指定场所自主推进资料、实验和整理三个科研阶段；实验可能失败并需要实际重试，组会反馈只给予本人实际到场的研究生。可切换到“人物故事”追看相关事件。六周压缩的虚构教学和考试场景包含四门虚构课程，本科生依据个人兴趣选择课程，容量和时间冲突可能导致选课失败；个人课表与考试依选课生成，实际行动决定出勤。已选数学的学生收到每周练习，需投入两个时段，可能未按时提交。按虚构权重结算模拟考试及成绩，通过后取得学分；未通过可参加一次模拟补考。支持模拟缓考、补考和一次跨周重修；真实学期与学校当期规则仍待进一步建模。图书馆提供示意的自习、借还与研讨区域；人物自主借还虚构馆藏，并可以为小组任务预约下一时段的研讨间，预约不保证有人到场。

两个虚构社团在公开招新期间接受自主申请，成员可选择参加每周活动、退出或提议跨周作品；作品须经过实际邀请、准备与到场，展示场地使用独立预约。

课间办事和排队可能影响下一节课的到达时间；食堂有虚构窗口与队列，饭约按双方实际行动结算。饥饿时身在宿舍的人可能选择食堂送餐；送到楼下后需要本人取餐才会进食，也可能错过，价格和时间为模拟值。同寝人物可以借还物品、商量晚间作息；雁南园、雁北园及宿舍 IV 区按房间分配。日历包含虚构的春日校园活动和校园美食节，人物自主选择是否参加；天气为确定性的模拟天气，不是真实预报。

人物会收到虚构包裹通知，自行前往学生活动中心取件，逾期包裹仍需本人处理。每栋宿舍楼有两台洗衣机，同一时段竞争按轮转顺序处理；衣物从下一时段起由本人回原楼取回，取回前机器仍被占用，调宿也不会转移衣物。

图书借完后人物可选择候补；可借副本按候补顺序保留并通知本人，期限内到馆才能借走，也可取消，过期后递补。餐厅的虚构周菜单会影响个人用餐选择；吃饭和等待仍以实际到场为准。

“存档与设置”可在新建世界时选择开启预算、兼职与压力实验，默认关闭；选项随世界存档和重放保存。余额和压力是虚构游戏数值，实际用餐或订餐才扣费，余额不足可选择免费基础餐；兼职需要本人到场完成，压力可以通过休息或自主求助缓解，求助需要熟人到场并同意。

六周末尾有虚构短假期，人物可自主留校或暂时离校并在预计时段返校；离校时不参与校园现场互动、服务或兼职，待处理事项仍按原规则保留。

参考示意图为 2025 年版本，现实建设情况可能已有变化；游戏地点和规则为虚构设定。

生活细节参考了[北邮沙河校区图书馆馆藏与服务分布](https://libportal.bupt.edu.cn/a/ruguanzhinan/guancangfenbu/)、[北邮餐饮服务介绍](https://hq.bupt.edu.cn/info/1006/1096.htm)及[校园美食节活动](https://hq.bupt.edu.cn/info/1010/1612.htm)，游戏中的活动日期、服务、价格和时间为虚构规则，不应当作现实指南。

## 本地运行

Node.js 22.12+，建议 Node.js 24 LTS：

```sh
git clone https://github.com/L8848-Li/VirtualCampus.git
cd VirtualCampus
npm ci
npm run dev
```

访问 http://127.0.0.1:8765 。端口被占用时：`npm run dev -- --port 8766`。

构建静态文件：`npm run build`，本机检查构建结果：`npm run preview`。本版需要通过开发服务或静态 HTTP 服务打开，已从双击 HTML 的原型迁移到模块化工程。

## 开始观察

1. 在“存档与设置”中输入种子、新建世界；单步或自动推进六周、每天四时段。
2. 用地图加减按钮缩放，放大后拖动；点击地点圈点，在右侧查看全部在场人物。选中人物后查看状态，用 ☆ 关注最多三人。
3. 使用“人物故事”切换到故事、共同事务和关系图；关系图可切换 TA 看别人 / 别人看 TA，跟随观察可定位角色所在地点。
4. 重排宿舍、随机分组或举办社团开放日，改变相遇与协作条件。
5. 展开“那些还惦记着的事”，追看饭约、报告和兴趣小聚的完整经过；分清真实发生的事与人物各自的理解。
6. 留意“想和大家做点什么”：谁提出了愿望、谁愿意帮忙、谁最后真的到场。
7. 校园手记归档每日代表片段，重放验证同版本、种子与干预的一致性。

每次推进与干预自动保存到当前浏览器。导出 / 导入带版本和校验的 JSON 可转移或备份。v0.17.0 使用独立的本机存档键，保留旧版记录，暂不支持跨引擎版本导入。发现 v0.16 存档时可下载原始备份，新版本需新建世界。没有账号或云同步。

## 技术结构

- `src/engine.ts` 保留世界操作和存档入口；`src/core/tick.ts` 按固定阶段推进既有规则。当前状态、已提交事件和紧凑评分分开管理，历史校验随新增事件更新。
- `src/controller/` 将模拟结果发布为界面快照，并管理播放和浏览器本地存档；`src/components/` 与 `src/App.vue` 负责地图、人物档案和事件展示。
- 项目是本地运行的静态前端，没有独立后端。存档保存在浏览器本地；清理浏览器数据前可导出 JSON 备份。
- 改变模拟结果的规则需要更新引擎版本和存档键，并检查同版本的种子、干预和重放。事件记录用于追溯实际行动，人物决策只使用本人可获得的信息。

详细说明见[架构与存档](docs/ARCHITECTURE.md)、[版本迁移说明](docs/MIGRATION.md)和[轻量化验证报告](docs/PERFORMANCE.md)。

## 验证

```sh
npm test                   # 常规规则、场景和代表种子测试
npm run test:full          # 全部测试，100 种子 × 生活实验关闭/开启
npm run verify             # 类型检查 + 完整测试 + 两类行为评估 + 构建
```

`npm run test:replay:full` 可单独运行完整重放检查。测试用两个独立世界逐时段核对当前状态、新增事件及评分，并对种子 0、1、99 在关键时段导入后续跑至结束。常规和监听测试都只使用一个工作线程，并保留文件隔离。原版 v0.16 的逐时段行为摘要用于核对决策、事件顺序、评分和随机序列；所有定向规则断言继续保留。

`npm run evaluate` 检查 100 个种子的首周行为，并与原版参考指标比较。`npm run evaluate:semester` 运行 30 组共享的科研、社团、选课场景及 30 对生活实验场景，验证完整学期的恢复和资源边界。原有单项评估脚本仍可使用。报告生成到本地 `internal-docs/reports/`，不随 Git 提交。

CI 在 Node 24 执行完整 `verify`，在 Node 22 执行类型检查、常规测试和构建。同分支的新提交会取消旧验证；单次验证只进行一次类型检查。

事件流每页 100 条、故事卡每页 6 张、故事经过每页 50 条；可翻页访问全部历史。评分详情在打开事件时还原，因果追溯会临时定位到对应事件，并允许返回原筛选和分页位置。

性能基准使用 `node --experimental-strip-types scripts/benchmark-save.mjs`；每次采集包含冷启动、预热和五次重复。浏览器开发模式 `?perf` 使用独立存档空间，显示交互 P95，并记录采样堆大小与 DOM 元素数。测量条件及未达目标项目见验证报告。
